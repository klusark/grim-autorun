# Plan: the tests, and the collision differences

State on 2026-10-24 evening. Tiers: A = offline in the game's own Lua 3.1 (`tools/lua31/run.sh`, 59 cases, 1 s);
B/C = in the game (`test_nav.lua`: unit 57, walk 40, moving target 96, collision 81). ScummVM runs the in-game
suite in about 60 s of wall time (deterministic `--sim-fps`); the original takes 25 minutes (real time: unit 7.5 min,
walk 2 min, moving target 12 min, collision 3.5 min). The two engines agree on 260 of 274 cases.

---------------------------------------------------------------------------------------------------------------

## 1. Reproducibility

Every case must give the same answer on every run, on each engine, alone or in the suite. Today three cases depend
on what ran before them (`door_from_inside` failed in the suite, passed alone) or on the state the game is left in.

1. **Isolation per case.** `ar_nt_place` resets everything a case can leave behind, in one function `ar_nt_reset`:
   collision modes and scales of Manny and of every actor a case moved (`AR_COLL` knows them), `is_running`,
   `is_climbing`, costume (`manny:default()` when the costume is not the set's), the held item, boxes shrunk, the
   constraint (`SetActorConstrain nil`, `stairman`/`curbman` restarted), head look, `AR_OBST`/`AR_NAV` caches of the
   planner, the follower's globals (`AR_FOLLOW_*`, `AR_TELE_*`). Actors a case brought in (`velasco`, the moving-target
   copies) are taken out again in the same function.
2. **Settling.** After `switch_to_set` the scripts of the set run for a frame or two (ch57's `at.watch_manny`,
   `rf`'s pigeons): the placement waits until `cutSceneLevel == 0`, no `Sentence`, and Manny's position has not changed
   for 3 frames, with a cap, instead of the fixed `sleep_for(500)`.
3. **Order independence check.** A run mode `AR_NT_SHUFFLE = seed` runs the cases in a seeded random order (the game
   has `random()`; a Lua LCG gives the same order on both engines). The ScummVM suite runs twice with different seeds
   in `test_all.sh`; a case whose result differs between orders is reported as order-dependent, by name.
4. **Flake detection.** `test_all.sh` runs the ScummVM suite 3 times and `tools/compare_navtest.py` over the three
   logs; a case that is not the same three times is listed under "flaky", and is a bug to fix, not to retry.
5. **The original's randomness.** The original is not deterministic (ch13 passed on one run and failed on the next,
   ch55 the same). Causes to pin down with the per-frame trace (section 4): idle animations started from `random()`,
   the frame time (`GRIM_FPS=60` is set by `grimrun2`, but `system.frameTime` was seen at 17 ms, i.e. not locked), the
   Lua task order. Measure first: the trace of a case run 3 times on the original, diffed frame by frame.
6. **Expected values recorded, not typed.** `nav_coll_expect.lua` is the model: the expected end points come from a
   run on the original and are checked in. The same for the ways of the unit cases (`nav_expect_original.lua`,
   generated by `tools/record_original.py` from a `grimdebug.log`): a unit case passes on ScummVM when its way is the
   way the original planned (same text), not only when it reaches the goal.

## 2. Speed

1. **The original, 25 min to 8 min.**
   * Group the cases by set and run them in that order (one `switch_to_set` per set instead of per case): the set
     switches with their settling are 4 to 6 s each, about 90 of them.
   * The moving-target tier is 12 minutes for 96 cases because every one walks 2 to 4 m at walking speed and waits for
     the actor to arrive. Run (`set_run(TRUE)`), and cut the ring from 4 starts x 8 routes to the 12 that found bugs
     (still, moving, fast, across, from each start that is not a repeat), keeping the full ring as `AR_NT_FULL = TRUE`.
   * Collision: 150 frames per case where the collision happens within 30; stop at 40 frames after the first contact
     (section 4 wants the trace anyway).
   * The frame limiter: `patch_framelimit.py` exists. If the original can run at 120 fps with `GRIM_FPS=120` and
     `system.frameTime` follows, the walks halve. To be measured against determinism (1.5): a changed frame time
     changes the results, so the recorded values must be re-recorded at the chosen rate, once.
2. **ScummVM, 60 s to 30 s.** Same grouping by set; `--sim-fps` already makes it run as fast as the CPU goes, so the
   wall time is CPU: the planner's big searches (3063 cells for the re door) are the cost; the `AR_SLICE` yield adds
   frames. Cache the world (`ar_w`) per set across cases (it is per set already; check it is not rebuilt).
3. **More in tier A.** Tier A runs in 1 s and needs no game. Two things it cannot do today that it could:
   * **An offline follower** (`tools/lua31/sim.lua`): a kinematic Manny (walk rate, turn rate, the engine's
     `walkForward` along the sectors with the exit-edge reflection, `SetActorConstrain` on stairs, the sector clamp)
     driven by the real follower code. It will not be the engine, but it catches the follower's logic errors (held-up
     handling, wiggle, replan loops, the stair turn, the obstacle detour) in milliseconds, with the real sector data.
     The collision model goes in once section 4 has settled what it is.
   * **Generated cases from the full run** (section 3.1) run offline first.
4. **One command.** `sh test_all.sh [scummvm|original|offline|all]`: builds, runs the tiers, compares with the
   recorded originals, writes `logs/navtest_summary.md` (counts per tier, the failures with their lines, the flaky
   list, the differences between engines). Today it is four commands and a grep.

## 3. Coverage

What the suite does not test today, in the order of what has bitten:

1. **Every walk of the game.** The full run's log has, for each `go:`/`do:`/`walk` line, where Manny stood and what
   the goal was. `tools/gen_cases.py all_pass1.log` turns them into unit cases (`nav_cases_run.lua`, several hundred):
   the way must exist, end in the door's sector or at the point, use the links the run used. Offline in a second;
   a planner change that breaks a chapter is found before a 7-minute run. The walk versions run in the game in a
   separate, slower tier.
2. **Collisions in the chapters.** `grep set_collision_mode` over the scripts gives every actor with a box or a
   sphere (Glottis in bl, the bonewagon in na/sg, Chepito in mn, Meche in bl, Domino in do, the signpost in sg,
   Velasco in re). A case per site: Manny placed next to it, the walk past it, the end point recorded on the
   original. Plus the planner's learned-obstacle cases for each (does the way go round, does the walk end in range).
3. **Engine-difference regressions.** One case per difference that was found and fixed, with the original's values:
   `SetActorRot` turning flag (ch38), `IsPointInSector` visibility, `SetActorConstrain` on stairs (the line from the
   heading), box collision (ch13), sphere centres, start_script timing (E4, measured not immediate). They pin the
   fixes in `engines/grim` and tell when a ScummVM change elsewhere undoes one.
4. **Triggers and scenes.** The hot sectors with `walkOut`/`climbOut` that take the walk over: the garage elevator
   trigger (wiggle timing), the sewer ladders (sh, at, th), the plunge trigger (re), doors whose scene sends Manny
   back (`waits >= 3`). A case each, walk tier, both engines.
5. **Carried state.** Shrunk boxes with each shrinkable set, running vs walking, holding an item through a door
   (`ar_hold` then `ar_go`), the head joints after a scene (`ar_fix_head`).
6. **Teleports.** The learned links (`PutActorAt` hook): a case that walks into a cheat box, is teleported, and plans
   the rest from the landing; the cheat boxes of every set (from `AR_SETS`) as generated cases.
7. **Negative cases.** Walks that must fail cleanly: a goal off the floor by more than 1.5 m, a door whose sectors are
   all off, a set with no floor under Manny; the budget: the walk must end within its budget and say why.
8. **The set-file loader against the dumps**, for every set, not the 8 of today: the checksum of each set's sectors
   from the loader equals the one ScummVM's `DumpSectors` gives (ScummVM only, development tier).

## 4. Usefulness

1. **A failure says how to reproduce it.** Each FAIL line gets the one command that runs that case alone on each
   engine, and the way/positions in a form `tools/plot_case.py` draws (the set's sectors, the way, Manny's trace).
2. **Per-frame traces on demand.** `AR_NT_TRACE = TRUE` logs Manny's position, yaw, sector and the engine's
   `is_moving` every frame of a walk or collision case (`NAVTRACE id frame x y z yaw`). `tools/compare_trace.py` prints
   the first frame where two traces diverge by more than 1 cm. This is the tool section 5 needs.
3. **Compare engines automatically.** `compare_navtest.py` runs in `test_all.sh` against the last original log and
   compares the way strings of unit cases, not only PASS/FAIL (two engines can both pass with different ways).
4. **Trend file.** `logs/navtest_history.tsv`: one line per run (date, engine, counts per tier, flaky, differences);
   `NAV_PLAN.md` section 8 points at it.
5. **Tier docs.** A short `TESTS.md`: how to add a case (the fields, which tier it lands in), how to record the
   original, how to read a failure.

## 5. The collision differences: how to fix them

What is known from the original (Ghidra, `GRIMFANDANGO.EXE` v1.01):

* Collision runs **once per frame**, in `FUN_004939a0`, for every actor whose position changed this frame (it compares
  pos +0xc with the previous pos +0x18), after all the walking of the frame; `FUN_004939f0(actor)` tests the mover
  against every other actor with a mode (+0x3f0 != 0). ScummVM tests in `moveTo`, per sector sub-step of
  `walkForward`, and again in `Actor::update` for all actors. The order and the number of tests differ.
* **Gate:** spheres first: both centres are the model's box centre (the 3rd vector after the radius in the .3do,
  transformed by the actor's full matrix, `FUN_0044fee0`), radii `model->radius * collisionScale`. Only when the
  spheres touch is the mode of the *other* actor looked at.
* **Sphere (mode 2):** the mover is pushed along the line from the other's centre to (r1 + r2) apart, then
  `FUN_00490870` (set position, with the sector clamp), both actors get the collided flag (+0x3f8), callback.
* **Box (mode 1):** the mover's position goes to the other's local frame (`FUN_0044ff50` with the matrix: pitch and
  roll too, not only the yaw); the box is the **model's own min/max from the file** (+0x60..+0x74 of the model),
  scaled by the other's collision scale, grown by the mover's radius; strictly inside on all six axes. Then
  `FUN_00494100` (the entry face from the move prev->cur taken back 10x, with its early `return 0` unless the
  remaining direction is exactly along the normal, so that in practice it fails) and `FUN_004922d0` (push out through
  the nearest side, +0.01, in the order y+, y-, x+, x-). Then the mover's prev position (+0x18) is set to the new
  position, `FUN_00490870`, and when the mover was walking a path (`+8 & 1`) `FUN_00491650` re-plans its path from
  the new position.
* ScummVM today: my `handleBoxCollision` (yaw-only frame, ScummVM's recomputed vertex bbox, face logic that may differ
  from `FUN_00494100`), sphere centres on the box centre (done), per sub-step.

The 10 remaining differences fall in two groups: the sphere cases at radius 0.50 (0.08 to 0.26 m off) and three box
cases (0.06 m along the approach axis for `box_0_0_35`/`box_0_180_35`; 0.3 m sideways for `box_140_270_*`, the slide
goes the other way).

Steps, each with the test that shows it:

1. **Make the test see the first divergence, not the 150th frame.** The grid cases steer toward the actor every
   frame; after contact Manny slides and turns for 120 more frames, and any 1 mm difference compounds into 0.2 m.
   Add `collision_static_*` variants: a fixed heading, `walk_forward` only, 40 frames, no steering; and the per-frame
   trace (4.2) on both engines. Record on the original. Compare traces: the first frame off by more than 1 cm is the
   bug, and says whether it is the contact frame (geometry) or a later one (slide/sector clamp/order).
2. **Use the file's box.** Read the min and max vectors of the .3do (the two before the centre) into `Model::_bboxMin/
   _bboxMax` and use them in `handleBoxCollision` and `getBBoxInfo`; keep the vertex-computed box for EMI and text
   models without them. Test: `collision_box_0_0_35`, `box_0_180_35` (the 6 cm along the axis is about the size of the
   difference between the two boxes).
3. **The full matrix for the local frame.** Build the other actor's matrix from pitch, yaw, roll as the original does
   and transform with it (ScummVM has `Math::Matrix4` / the actor's `getFinalMatrix`); the yaw-only frame is wrong for
   any tilted actor and may be wrong for Velasco (his rotation is `(0, 140, 0)` so probably not, but the test says).
4. **Port `FUN_00494100` and `FUN_004922d0` literally**, including the early return, and drop my face/tangent code
   unless the trace of the original shows the face slide ever running. Test: `box_140_270_*` (the slide direction).
5. **Once per frame, after the walk.** Move the collision test out of `moveTo`'s sub-steps: `walkForward` moves along
   the sectors as now, and at the end of the actor's update one collision pass runs against the frame's movement
   (prev pos -> pos), for the actors that moved, in the original's order (the actor list order). Remove the second
   pass in `Actor::update` for Grim (keep EMI as it is). This changes every collision in the game: the full ScummVM
   run and the chapter collision cases (3.2) are the regression. Test: the sphere cases at radius 0.50, where the
   difference grows along the slide (several pushes per frame vs one).
6. **The sector clamp after the push.** `FUN_00490870` is what the original does with the pushed position; see whether
   it clamps to the walk sectors (it is the same call as `PutActorAt`'s), and do the same (ScummVM's `moveTo` adds the
   vector without clamping; `walkForward` clamps before). Test: the Velasco sliver case (`collision_box_velasco`,
   0.0185 m off today, on a 25 cm sliver).
7. **The path re-plan on collision** (`FUN_00491650` when the actor walked a path): ScummVM's `WalkActorTo` path is
   not re-planned after a push. Matters for NPCs that walk into Manny (Velasco walking down to the car with Manny in
   the way), not for the key-driven walks of the run. A case: Velasco's `walk_down_to_car` with Manny placed on his
   way, where does he end on each engine.
8. **Re-record, then tighten.** After 2-6 the grid is re-recorded on the original (the test harness changed), the
   tolerance goes from 5 cm to 2 cm, and the static variants to 1 cm per frame over 40 frames. Whatever still differs
   is listed in NAV_PLAN.md section 8 with its trace.

Order: 1 first (it is the instrument), then 2 and 4 (cheap, likely to fix 5 of the 10), then 5 (structural, needs the
full run), then 3, 6, 7. Each step: build, the collision tier on ScummVM against the recorded original, one full
ScummVM pass before moving on from 5.
